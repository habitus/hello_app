# Project instructions for Claude

## Learning log (`LEARNING_LOG.md`)

The user is learning how to build production-grade software. Maintain `LEARNING_LOG.md` throughout every session.

**When to update:** At the end of any turn that explains a new concept, makes a project decision, or raises or answers a question worth revisiting. Commit and push the update with the other changes from that turn.

**What deserves inclusion:**
- Concepts the user asked about or needed explaining (jargon, tools, practices).
- Decisions and the reasons for them.
- Questions the user asked, indexed to where the answer lives.
- Open questions that still need answers. Remove them once they are answered.

**What to leave out:** Small talk, tool errors, and details that only matter for one moment.

**Writing rules:**
- Never use em dashes.
- Never use the "It's not X. It's Y." construction.
- Write in full sentences wherever possible.
- Give each concept a plain definition, an analogy, a concrete example (tied to the project where possible), and a "Why it matters" line.
- Make each entry stand on its own so it can be understood months later without the conversation.
- Keep entries accurate and complete. If a later exchange corrects or deepens an earlier entry, edit that entry instead of adding a duplicate.
- Date each entry.
